Abstract

Object-level mapping and topological navigation reason about whole objects, yet the correspondences they rely on are computed over keypoints or pixels and only aggregated into objects afterwards. A recent line of work removes this detour by matching directly at the level of instance segments: a class-agnostic segmenter partitions each image, and per-segment descriptors are pooled from large 3D foundation models over the masks. This shifts the open question to how frozen foundation features should be processed once the unit of matching is a segment. We introduce MuViSeg, three learned matching heads: a LightGlue-style attention head on frozen MASt3R descriptors; a DPT-style multi-scale fusion module that exposes layered spatial detail from VGGT before pooling; and, as our main contribution, a joint multi-view head that attends over segments from several views at once, recovering transitive correspondences that pairwise matchers cannot express. In zero-shot evaluation on Replica and Virtual KITTI 2 across 0–180 degree viewpoint changes, our heads consistently improve over a parameter-free Sinkhorn matcher on the same backbone. Across 102 HM3D navigation episodes, direct segment matchers and sparse keypoint aggregation are statistically indistinguishable, while dense matches voted into masks lose 13.7–18.0 SPL.

Method

MASt3R features depend on the image pair, because its decoder cross-attends between the two views. They suit a strong pairwise head but cannot be shared across a variable set of views. VGGT features are pair-independent, so the joint multi-view head is built on VGGT. The joint model is trained with N = 4 views and runs at other N without retraining. All heads are trained on ScanNet++ only.

Real images

Replica and Virtual KITTI 2 are rendered. On held-out ScanNet++ validation scenes (real images, in-domain rather than zero-shot), all three heads match or exceed the Sinkhorn baseline: AUPRC 89.6 (SegVGGT-DPT), 90.6 (Joint) and 91.0 (LGv2), against 88.9.

The joint model on an in-house robot recording, with no retraining. Segments are FastSAM proposals, and each colour is one track. There is no ground truth for this recording, so these videos are qualitative.

Code

Training, evaluation and inference code is at github.com/muviseg/muviseg-codeRelease, and the checkpoints are on Hugging Face. To install and run an evaluation:

git clone https://github.com/muviseg/muviseg-codeRelease.git
cd muviseg-codeRelease
uv sync
bash setup_third_party.sh
uv run python scripts/download_checkpoints.py

export MUVISEG_DATA_ROOT=/path/to/datasets
uv run python scripts/eval.py --dataset replica --config configs/eval/replica_segvggt_joint.yaml

The repository README covers training, inference on your own frames, the navigation experiments, and which reported numbers can be reproduced exactly.
